# Пульт зависших задач

Задача комнаты не должна стоять молча. В каждый момент живая задача держится
одним из четырёх: живой арендой исполнителя, вопросом владельцу, паузой владельца
или датированным ожиданием (`waiting_until`). Нет ничего из этого дольше двух
суток - задача зависла, и Вера спрашивает владельца простым текстом, что делать.

До пульта сторож (`watchdog.py`) смотрел только задачи с держателем аренды.
Задачи без держателя - открытые, которые никто не взял, и заблокированные после
release - для него не существовали. На 11.11.2026 таких было 52, ни одна не
двигалась, вопросов владельцу по ним было открыто 6.

## Правило

`stall_rules.is_stalled(StallFacts, now)` - чистая функция. Задача зависла, если:

- статус `open` или `blocked`;
- нет живой аренды, нет блока владельца (вопрос, ожидание владельца, пауза);
- нет `recovery_hold` и делегированной аттестации - у них свои маршруты (recover у
  владельца, аттестация у dot), пульт их не подменяет;
- `waiting_until` не в будущем и отсрочка владельца не в будущем;
- последняя активность (`stall.last_activity`: максимум из `updated_at`,
  `last_progress_at`, `created_at`) старше `STALL_AFTER` (2 суток).

`stall.stalled_tasks(now)` собирает факты по каждой активной задаче
(`stall.facts_of`) и отдаёт список `Stalled`, самые давние первыми.

## Пульт в Telegram

Одно сообщение владельцу, которое правится на месте, а не лента вопросов.
Состояние - одна строка `stall_board` (миграция `063_stall_board.sql`, модель
`StallBoardRow`): номер сообщения, когда отправлено, ревизия, текущая задача,
режим (`ask` / `confirm_cancel`), пропущенные кнопкой "Следующая".

- `stall_board.plan()` решает, что делать: `none`, `edit` или `send` (объект
  `Plan`). Новое сообщение - только если есть зависшие задачи и прошлое отправлено
  больше суток назад (`NOTIFY_EVERY`) или его нет. Всё остальное время - правка
  того же сообщения: правка не будит владельца звуком.
- `pick_current` держит текущую задачу, пока она висит, иначе берёт первую
  непропущенную. `render` строит текст (`question_text`, склонение - `days_word`,
  обрезка - `short`) и кнопки; `key_of` - ключ задачи `room/task_id`.
- Каждая перерисовка с новым текстом поднимает ревизию. Ревизия уходит в
  callback-данные `sb:<действие>:<rev>`; нажатие по устаревшему пульту ничего не
  меняет и отвечает "Пульт обновился". Иначе кнопка применилась бы к задаче,
  которую владелец уже не видит.
- `press` применяет нажатие. "Отменить" сначала переводит пульт в режим
  подтверждения; отменить можно только кнопкой "Да, отменить".
- `remember_sent` запоминает номер отправленного сообщения, `forget_message` -
  сообщение пропало в Telegram (владелец удалил), следующий проход пришлёт новое.

Бот (`bot_telegram/stall_worker.py`): `run_forever` раз в 5 минут вызывает `sync`,
который приводит сообщение к `plan`. При `send` прежнее сообщение удаляется -
в чате остаётся один пульт. `markup` собирает inline-кнопки; кнопки ловит
`on_stall_board` в `bot.py` (только владелец) и зовёт `stall_worker.press`, затем
сразу перерисовывает. Цикл и нажатия делят один замок. Включается флагом
`STALL_BOARD_ENABLED=1` (`enabled`), по умолчанию выключен: сначала миграция 063.

## Действия владельца

`room/owner_task_actions.py`, без аренды и fencing-токена, как пауза
(`owner_actions.py`). Каждое пишет одно событие с `data.by="owner"` и каналом
`via` (`telegram` или `dashboard`); повтор того же действия ничего не пишет.

| Действие | Что делает |
|---|---|
| `continue_by_owner` | Задача в `open` с `auto_pickup=true`, пауза владельца снимается (`resumed`, затем `unblocked`). Чужую живую аренду не трогает - `TaskBusy`. |
| `snooze_by_owner` | Событие `watchdog_action` с `data.action="owner_snooze"` и `until`; задача уходит с пульта на `SNOOZE` (3 суток). Статус и `updated_at` не меняются. |
| `cancel_by_owner` | Отмена любой незавершённой задачи, в том числе под чужой арендой; держатель при следующей записи получает `StaleLease`. Открытые вопросы снимаются. Аттестованная задача - только через dot. |
| `owner_actions.pause_by_owner` | Прежняя пауза владельца; принимает `via`. |

Общая часть отмены вынесена в `task_cancel.apply_cancel`: её зовут и штатный
`room_task_cancel` агента, и `cancel_by_owner`.

Новых видов событий нет, миграция CHECK не нужна: используются существующие
`cancelled`, `unblocked`, `resumed`, `paused`, `watchdog_action`.

## Страница `/office/hourly`

В карточке задачи - кнопки владельца (`office_owner_actions_view.owner_actions_bar`):
Продолжить, Ждать 3 дня, Пауза или Снять паузу, Отменить (с подтверждением).
Формы шлют POST на `/tasks/{room}/{task_id}/move/{continue|snooze|cancel}`
(маршрут `task_move`, сервис `owner_move`) и на прежние `/pause` и `/resume`,
все за `owner_post_gate`. Скрипт страницы отправляет форму без ухода со
страницы и перечитывает карточку; закрытие окна после действия перезагружает доску.

Блок "Отмена владельца ожидает записи в Room" - задачи, которые владелец решил
отменить (запись dot для дашборда), но которые в комнате остались открытыми:
раньше отменить их мог только создатель. Кнопка "Отменить все" -
`POST /office/hourly/apply-cancellations` (`office_apply_cancellations`, сервис
`office_owner_cancel.apply_pending_cancellations`) отменяет их от имени владельца
с причиной, ссылающейся на запись Room с решением.

### Цвета кнопок

Кнопки владельца в карточке и "Отменить все" используют штатные классы темы
(`secondary`, `danger`, `sm` из `ui/css_controls.py`), а не свои цвета. Первая версия
задавала фон `var(--panel,#fff)`: такой переменной в тёмной теме нет, и кнопка
получала белый фон с белым унаследованным текстом (контраст 1:1). Тогда же
`--faint` в `ui/css_base.py` поднят с `#5c6475` до `#828a9c`: прежний цвет давал
2,7-3,4 на фонах темы, новый - не ниже 4,6 (порог WCAG AA - 4,5).
