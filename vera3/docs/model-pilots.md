# Пилоты моделей распознавания (сентябрь 2026)

Это **замер, а не внедрение**: в сервисах ничего не менялось. Цель —
понять, чем можно заменить или дополнить две дорогие/медленные части
media-worker и слушателя:

1. **фото** — сейчас vision через брокер: облако gemini (эталон качества) и
   локально на сервере `local/qwen3vl` (qwen3-vl-4b Q4_K_M, llama.cpp, 2 ядра;
   за 14 дней до 13.09.2026 — 3 949 успешных джоб, медиана 139 с, p90 213 с);
2. **речь** — слушатель на ноутбуке: OpenVINO whisper-large-v3-turbo int8 на NPU
   (см. [listener.md](./listener.md)).

Кандидаты: **PaddleOCR-VL-1.6** (0.9B, последняя версия семейства на
14.09.2026) и **nvidia parakeet-tdt-0.6b-v3** (сборка
`FluidInference/parakeet-tdt-0.6b-v3-ov`).

Машина: Acer Swift SFG14-75 — Core Ultra 7 258V (8 ядер), Arc 140V, NPU
AI Boost, 32 ГБ, OpenVINO 2026.3.1. Прод-сервер не использовался (там
свободно ~1.3 ГБ RAM из 7.7 и 2 ГБ своп уже занято — боевой хост).

## Метрики (`scripts/pilots/metrics.py`, тест `tests/unit/test_pilot_metrics.py`)

- **char_sim** — 1 − Левенштейн/длина по нормализованному тексту (регистр,
  markdown, пробелы). У gemini берётся только дословная часть после
  «Текст:» — описание OCR-модель не пишет и писать не должна. У qwen —
  тоже часть после «Текст:», промпт боевой.
- **tok_recall** — доля слов эталона, найденных в ответе (с кратностью).
- **num_recall** — доля чисел эталона (≥2 цифр), найденных в ответе;
  «1.250.000», «1,250,000» и «1 250 000» считаются одним числом.
- **loops** — ответ зациклился (одна строка ≥10 раз или уникальных < 1/3).
- **WER** — по словам, «ё=е», без пунктуации и регистра.
- Время — на картинку/файл после загрузки; память — peak working set
  процесса (вместе с torch/transformers у PaddleOCR-VL).

Медианы по 33 фото, если не сказано иное.

**Потолок 2 потока** (`INFERENCE_NUM_THREADS=2`, первые 6 фото, все

**NPU для PaddleOCR-VL не работает**: ноутбук OpenVINO сам исключает NPU,
при попытке — «Option DYNAMIC_QUANTIZATION_GROUP_SIZE is not supported»,

динамическими формами). Не обходили.

**qwen3-vl-4b на ноутбуке** запущен через готовую сборку
`OpenVINO/Qwen3-VL-4B-Instruct-int4-ov` (не тот же GGUF, что на сервере, —
сравнение по модели, а не по бинарнику). Фото 1928×2560 на CPU роняло его
по памяти («Failed to allocate»), поэтому длинная сторона ужимается до
1280. Сохранённые на проде ответы `local/qwen3vl` для этой выборки не
годились: из 7 003 фото с gemini-ответом и 3 938 с локальным пересекаются
только 2.

### Что видно глазами (обезличено)

- Скриншот переписки о цене футболок: PaddleOCR-VL переписал весь чат
  дословно (char_sim 0.99), qwen дал описание и из текста только
  «Price : 209.000/pcs».
- Товарный чек на русском/английском: PaddleOCR-VL выдал «100 VND» раз
  сорок подряд до лимита токенов — это и есть «зацикливание». Эталон gemini
  — полная таблица позиций.
- Интерфейс CRM с пустой таблицей: PaddleOCR-VL — только подписи
  («Заявки на обучение, Поиск, ФИО…»), без смысла «таблица пустая,
  обведено число 5». Описания он не даёт в принципе.

### Вывод по фото

- **Как замена gemini — не годится**: нет описания сцены (а для фото без
  текста — людей, мест, вещей — это весь ответ), 3–5 из 33 зацикливаются
  на повторяющихся строках таблиц/чеков и сжигают лимит токенов.
- **Как замена `local/qwen3vl` в роли OCR — годится и лучше**: слов в 1.5
  раза больше (0.76 против 0.53), числа 0.82 против 0.61, по вьетнамским
  чекам разрыв самый большой. Правильная форма — **дополнение**: qwen (или
  gemini) пишет 1–3 предложения описания, PaddleOCR-VL — блок «Текст:».
- **На сервер при ≤1 ГБ свободной памяти — нет.** Одни веса — 1.4 ГБ
  (vision fp 878 МБ, LLM int8 362 МБ, эмбеддинги 212 МБ), рабочий пик
  процесса 5.9–6.1 ГБ. Реалистичный потолок для сервера — от ~2.5 ГБ под
  процесс, и то после переписывания обвязки без torch/transformers и с
  int8-квантованием vision-части (не замерялось). Со свободными 1–1.3 ГБ
  запускать нельзя — вытеснит Postgres и брокер в своп.
- Время на 2 потоках (~50 с медиана, хвост до 5 мин) не лучше нынешних
  139 с настолько, чтобы окупить память.

## Пилот 2 — речь

| модель / устройство | ×реального (тёплый) | загрузка | пик памяти | CPU-сек на 753 с аудио | WER к проду ru / uk (медиана) |
|---|---|---|---|---|---|
| whisper-turbo int8, **NPU** (как слушатель) | 20× | 155 с холодная, 3 с с кэшем | 3.6 ГБ | 8 | 0.10 / 0.21 |
| whisper-turbo int8, CPU | 3.1× | 2 с | 2.1 ГБ | 779 | 0.10 / 0.20 |
| parakeet-v3, **NPU** | 53× | 46 с холодная, 0.5 с с кэшем | 1.6 ГБ | 15 | 0.11 / 0.25 |
| parakeet-v3, Arc GPU | 69× | 2 с | 1.7 ГБ | 21 | 0.12 / 0.22 |
| parakeet-v3, CPU | 12× | 2 с | 3.9 ГБ | 220 | 0.12 / 0.22 |
| whisper-turbo NPU **без языка** | 20× | — | 2.6 ГБ | 7 | 0.10 / **0.83** |

Parakeet ↔ whisper-NPU между собой: WER медиана ru 0.08, uk 0.20.

**NPU этого чипа parakeet тянет**: на NPU идёт энкодер (1.2 ГБ fp16,
статическое окно 15 с), мел-спектр, LSTM-предсказатель и joint — на CPU
(тысячи мелких вызовов, пересылка дороже счёта). Процессора съедено вдвое
больше, чем у whisper на NPU (15 против 8 с на 753 с аудио) — это жадный
декодер на Python (на C++ должно быть меньше — не замерялось).

**Своя обвязка** (`scripts/pilots/parakeet_ov.py`): у сборки нет Python-API,
жадный TDT-декодер повторяет C++ из FluidInference/eddy. Длинное голосовое
режется на куски ≤15 с в самой тихой точке последних 3 с. Первая версия
переносила состояние LSTM между кусками, как eddy, — и на 37-секундном
голосовом молча теряла ~8 с речи второго куска; с чистым состоянием на
каждый кусок текст полный. Таблица выше — после исправления.

### Спорные случаи (ручная оценка 5 самых расходящихся)

1. **Суржик, помеченный как `uk`** (речь почти вся русская, одна фраза
   украинская). Whisper с `<|uk|>` *перевёл* русскую речь на украинский.
   Parakeet записал как сказано, по-русски, но исказил название
   («кьютор … светнего центра»). По смыслу честнее parakeet.
2. **Короткое украинское, быстрая речь.** Whisper почти дословно совпал с
   продом; parakeet сломал начало («Доброго дров», «роботували») и в конце
   **сорвался в русский**: «Спасибо, сейчас найду кого-то нормально» вместо
   «Сподіваюся, що знайдуть когось нормального». Лучше whisper.
3. **Сумма голосом (ru).** Whisper: «2,850 млн.»; parakeet: «два восемьсот
   пятьдесят, два миллиона восемьсот пятьдесят». Parakeet не нормализует
   числа в цифры — для поиска по суммам хуже, в WER штраф ложный.
4. **Украинский с матом и именем.** Оба ошиблись в первом слове по-разному,
   остальное одинаково. Ничья.
5. **Длинное украинское про промпты и агентов (IT-жаргон).** Оба близки;
   whisper держит «Клод», «IP-шки»; parakeet — «вклад», «Vicon», «МСП» и
   один раз «проект» вместо «проєкт». Чуть лучше whisper.

### Украинский на деле

Parakeet язык **не спрашивает и сам не переводит** — это его плюс против
whisper, который без явного `<|uk|>` переводит украинскую речь на русский
(WER 0.83), а с явным — переводит на украинский русскую (случай 1). Но на
быстрой украинской речи parakeet заметно слабее (0.22–0.25 против 0.20–0.21)
и способен посреди фразы перейти на русский (случай 2).

### Вывод по речи

- **Как замена whisper-turbo в слушателе — пока нет.** Качество на русском
  равное, на украинском хуже, плюс срывы языка и числа словами. Выигрыш —
  скорость (53× против 20× на NPU) и память (1.6 против 3.6 ГБ пика), а
  слушателю скорость не нужна: он уже работает быстрее реального в 20 раз
  при 22% ядра.
- **Дополнение, где оно полезно**: чат со смешанным ru/uk, где язык заранее
  неизвестен — parakeet не переводит. Проверять на отдельной выборке
  суржика, прежде чем что-то решать.
- **Для сервера (2 ядра, ≤1 ГБ)**: CPU-режим 12× реального на 8 ядрах
  ноутбука, пик 3.9 ГБ — на сервер не влезает так же, как whisper.

## Риски внедрения (если к этому вернуться)

- PaddleOCR-VL: зацикливание на табличных строках → нужен детектор повторов
  и `max_new_tokens` ~512; нет NPU; обвязка ноутбука тянет torch и
  transformers 4.54 (закреплённая версия), для сервиса её придётся
  переписать на чистый OpenVINO.
- Parakeet: сборка сторонняя (FluidInference), Python-обвязки нет —
  декодер свой, нарезка своя; ошибка в переносе состояния уже теряла речь
  молча. Числа словами. Лицензия CC-BY-4.0 (атрибуция).
- WER «к проду» — не точность: эталон сам whisper. Разница в 0.02–0.04
  на 10 файлах — в пределах шума.
- Выборка малая (33 фото, 19 голосовых) и смещена к фото с длинным
  «Текст:» — на фото без текста PaddleOCR-VL бесполезен вовсе.

## Как повторить

Всё на D: (на C: мало места): `HF_HOME=D:\pilots\hf`,
`PIP_CACHE_DIR=D:\pilots\pip-cache`, `TMP/TEMP=D:\pilots\tmp`.

```
py -3.12 -m venv D:\pilots\venv
D:\pilots\venv\Scripts\pip install --index-url https://download.pytorch.org/whl/cpu torch==2.8.0 torchvision==0.23.0
D:\pilots\venv\Scripts\pip install openvino==2026.3.1 openvino-tokenizers==2026.3.1.0 openvino-genai==2026.3.1.0 ^
    nncf pillow opencv-python huggingface-hub transformers==4.54.0 protobuf sentencepiece einops psutil datasets
cd vera3\scripts\pilots
python fetch_samples.py photo --per-group 13     # системный python, нужен ssh hetzner-root
python fetch_samples.py voice --per-group 10
D:\pilots\venv\Scripts\python ocr_convert.py      # PaddleOCR-VL-1.6 → IR
# parakeet: файлы FluidInference/parakeet-tdt-0.6b-v3-ov → D:\pilots\models\parakeet-v3
# qwen: OpenVINO/Qwen3-VL-4B-Instruct-int4-ov → D:\pilots\models\OpenVINO__Qwen3-VL-4B-Instruct-int4-ov
D:\pilots\venv\Scripts\python ocr_run.py GPU      # CPU; CPU --threads 2 --limit 6
D:\pilots\venv\Scripts\python vlm_run.py GPU      # то же
D:\pilots\venv\Scripts\python asr_run.py parakeet NPU   # CPU, GPU; whisper NPU [--language auto]
D:\pilots\venv\Scripts\python evaluate.py photo   # агрегаты
D:\pilots\venv\Scripts\python evaluate.py voice --disagreements 5   # + спорные случаи, печать локально
```

Файлы в `scripts/pilots/`: `fetch_samples.py` (выборка), `ocr_convert.py`,
`ocr_run.py`, `vlm_run.py` (фото), `parakeet_ov.py`, `asr_run.py` (речь),
`metrics.py` (чистые метрики, `gemini_ocr_part`, `char_similarity`,
`token_recall`, `number_recall`, `wer`), `evaluate.py` (сводка). Один
процесс = одна модель и устройство, чтобы пик памяти относился к ней.
Whisper берётся из модели слушателя `D:\vera-listener\models`.
